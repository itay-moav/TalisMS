# TalisMS v5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn TalisMS into a PHP 8.5-only, fully typed library (v5.0.0), checked by phpstan level max, covered 100% by phpunit, plus a small demo app that does user CRUD through every door.

**Architecture:** The library stays a chain-of-links framework: Door → TalisMain → Router → chain (filters → dependencies → business links) → renderable last link → emitter. v5 renames to camelCase (keeping the `a`/`i` prefixes, `CodeNNN`, `gogogo()`, `$Request`/`$Response`), fixes the bugs found in the audit, and adds `aDoor` (shared door logic) and `SpoolWorker` (the pure-PHP replacement for the Python queue listener). All app-shaped code moves into `demo/`.

**Tech Stack:** PHP 8.5.12, Composer 2.11, phpunit ^12, phpstan ^2 (level max), pcov for coverage, pcntl for signals.

**Spec:** `DOCS/superpowers/specs/2026-11-09-talis-v5-design.md`

**Signature source of truth:** `DOCS/local/2026-11-09-talis-v5-api-inventory.json`. It lists, for every file in `src/`, the exact v5 declaration of every member (`members[].new`), behaviour notes (`members[].note`) and the unit tests to write (`tests[]`), plus `consumer_renames` for the release notes. Each library task below says which inventory files it implements. **The "Inventory corrections" section below overrides the inventory wherever they disagree.**

## Global Constraints

- `composer.json`: `"php": ">=8.5"`. Nothing below 8.5 is supported.
- Every PHP file, including extension-less scripts such as `lord_commander`, starts with `declare(strict_types=1);`.
- Native types on every property, parameter and return. `#[\Override]` on every override and interface implementation.
- phpstan level `max`, paths `src`, `tests` and `demo`. No `ignoreErrors`, no baseline, no inline `@phpstan-ignore`.
- Coverage of `src/` is 100% of lines. Prefer seams to `@codeCoverageIgnore`. Any ignore is listed, with its reason, in `tests/README.md`.
- Naming: methods and properties are camelCase, constants UPPER_SNAKE_CASE. **Kept:**
  - the `a` prefix on abstract classes and the `i` prefix on interfaces
  - the `CodeNNN` classes and the lowercase `commons` namespace
  - `gogogo()`
  - the capitalized `$Request` and `$Response`
- Spelling fixes: `DoneSuccessfull` → `DoneSuccessful`, `AccessForbbiden` → `AccessForbidden`, `CliEmbeded` → `CliEmbedded`.
- Clean break: no `#[\Deprecated]`, no `class_alias`, no shims, no compatibility wrappers.
- `iLogger` keeps its exact methods: `debug(mixed $inp): void`, plus `info`/`warning`/`error`/`fatal(mixed $inp, bool $full_stack): void`.
- Logging only through `\Talis\TalisMain::logger()->method(...)`. No global `dbg`/`dbgn`/`dbgr`/`info`/`error`/... calls anywhere: library, demo or tests.
- Comments and docblocks are short, plain English and say what or why. Docblocks that only repeat the signature are deleted.
- **Private docs stay private.** `DOCS/local/` is git-ignored. It holds the API inventory and the per-consumer migration docs. No committed file may name or describe the owner's consumer apps. Before every commit, run `git grep -niE "<consumer-names-regex given by the orchestrator>"`; the output must be empty. The inventory's consumer use counts and notes stay in `DOCS/local/` only.
- **Never read, write or run anything** under the owner's consumer-app folders. The orchestrator gives their path in the task prompt; this file doesn't name it.
- Commit after each task on `master`. **Never push.** Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Per-task check command, run on the files the task touched: `vendor/bin/phpstan analyse <paths>` and `vendor/bin/phpunit <test paths>`. The whole-repo gates run in Task 13.

## Inventory corrections (these override the inventory JSON)

1. **One exception for bad chain entries:** `src/Talis/Exception/InvalidChainEntry.php`, `class InvalidChainEntry extends \Exception`, `__construct(string $reason, ?\Throwable $previous = null)`, message `"Bad chain link entry: {$reason}"`. There is no `InvalidChainLink.php`.
2. **New `src/Talis/Exception/InvalidParam.php`:** `class InvalidParam extends \Exception`, `__construct(string $paramName, string $reason, ?\Throwable $previous = null)`, message `"Param [{$paramName}] {$reason}"`.
3. **Get params are `array<array-key, mixed>` everywhere** (Request ctor, `getAllGetParams()`, `aRouter`, the filters).
4. **Remove `aFilter::stringValues()`.** `AddGetQueryStringOverriding` and `FormPostIntoGetOverride` build `new Request($Request->getUri(), array_replace($Request->getAllGetParams(), $_GET /* or $_POST */), $Request->getBody())`. Tests: `testArrayValueKept`, `testNumericKeysKept`.
5. **`GetFieldUInt::validate()`** reads `$this->Request->getAllGetParams()[$field] ?? null`. It is valid only if `is_string($v) && preg_match('/^[0-9]+$/D', $v) === 1`, and it calls no getter that throws. Render messages:
   - missing: `GET param [x] is missing`
   - otherwise: `GET param [x] is not an unsigned int, it is: [<value or debug type>]`
6. **`aDoor::dispatch()`** catches `\Talis\Exception\ParamNotFound|\Talis\Exception\InvalidParam` before `\Throwable` and returns `badInput($e->getMessage())`, a 400. Tests: `testDispatchMapsParamNotFoundTo400`, `testDispatchMapsInvalidParamTo400`.
7. **`Request::getParamOrFail(string $key): string`**, as the message inventory defines it. `Response::setMessage(string $message): string`. `begin(): static`, `setHeader(): static`, `getHeaders()` → `list<string>`.
8. **`aDoor::exceptionResponse()` and `badInput()`** run every message (and every `TalisErrorStack` line) through `mb_scrub($text, 'UTF-8')`. Test: `testExceptionWithInvalidUtf8MessageStillEmits500`.
9. **Contract (written in the docblocks of `aDoor`, `PayloadToJson200` and `PayloadToString200`):** a `render()` that throws must not have sent headers or output. `PayloadTo*` encode first and then send. Doors test: a `PayloadToJson200` fixture with an `INF` payload ends as an emitted 500.
10. **`Response::getStatus()`** returns a new `Code500` when no status was set (it does not store it). Also add `hasStatus(): bool`.
11. **Keep both `getParamExists()` and `getParamOrFail()`.** They behave the same. The `getParamExists` docblock says: "Same as getParamOrFail(); kept for existing callers."
12. **JSON errors in `PayloadToJson200`/`PayloadToString200`:** `\JsonException` propagates, and the door turns it into a 500.
13. **`ClassNotFound` and `FileNotFound`** stay, with typed constructors.
14. **Form bodies:** HTTP/Rest skip JSON decoding when the Content-Type is `application/x-www-form-urlencoded` or `multipart/form-data` (body = null; the data stays in `$_POST`). Any other non-empty body that is not a JSON object → 400.
15. **SpoolWorker leftovers:** at the start of `run()`, if `processing/` is not empty, log `warning('Spool has N file(s) left in processing/ from an earlier run; check and move them by hand', false)`. Nothing is moved automatically. `done/` and `failed/` keep the original file name.
16. **Release-note sed rules** are all `sed -E` (ERE), with no BSD-only `[[:<:]]` anchors. Word boundaries are written as `(^|[^A-Za-z0-9_])X([^A-Za-z0-9_]|$)` → `\1Y\2`.

## Review Focus

1. **Two doors writing users at the same time** (the web page plus the spool worker). Expected: no lost or corrupted records. Pinned by `UserStoreTest::testConcurrentCreatesFromForkedProcessesKeepEveryUser` (Task 10).
2. **Broken or missing data file:** first run with no `users.json`, an empty file, or invalid JSON. Expected:
   - missing or empty → treated as no users, and created on the first write
   - invalid JSON → a clear 500 error, and the file is **never overwritten**
   Pinned by `UserStoreTest::testMissingFileIsEmpty`, `testEmptyFileIsEmpty` and `testCorruptFileThrowsAndIsNotOverwritten` (Task 10).
3. **A spool file still being written when the worker scans.** Expected: only `*.json` files are picked up, so producers write `x.json.tmp` and then rename. Pinned by `SpoolWorkerTest::testTmpFilesAreIgnored` (Task 9).
4. **Rest URLs with a trailing slash, a query string, or `/api` in an unexpected place.** Expected: `/api/demo/user/`, `/api/demo/user?x=1` and `/api/demo/user` all route the same, and a URI outside the root gives a 404, not a 500. Pinned by `RestTest::testTrailingSlashAndQueryRouteTheSame` and `testUriOutsideRootIs404` (Task 8).
5. **Non-ASCII user data** (`"name": "Ünal Şahin"`). Expected: stored and returned unchanged through every door. Pinned by `UserStoreTest::testUnicodeRoundTrip` (Task 10) and by the Rest leg of `DemoThroughEveryDoorTest` (Task 12).
